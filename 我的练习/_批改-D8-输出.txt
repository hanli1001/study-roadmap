3. 只修掉前面 3 个语法错、不动顺序错 —— 会发生什么
======================================================================
绳子表 student_course 全部行：
    (1, 4, '高一')
    (2, 1, '高三')
    (3, 6, '高三')
    (4, 3, '高一')
    (5, 5, '高二')
绳子表行数 = 5

作业第 3 条查询实际会跑到什么：
   它写的是 SELECT * FROM student_courses  ->  表名不存在

假设改成正确的表名，再配一条 JOIN：
    course_id | 学生   | 课程 | class_name
    (1, '李三', '语文', '高一')
    (2, '张三', '数学', '高三')
    (4, '牛二', '物理', '高一')
    (5, '张贾瑞', '化学', '高二')
JOIN 出来行数 = 4  ← 绳子表是 5 行
绳子表里指向不存在学生的行： [(6,)]

4. 循环里那段 if/else 到底走了哪一边
======================================================================
rn 从 0 到 5 各跑一次，if 分支进入次数 = 6  else 分支进入次数 = 0
=> else 分支是死代码，永远走不到；b = rn 这行也没用（下一轮开头又被 -1 覆盖）

5. class_name 抄进绳子表之后：改一次名册，两份数据就对不上了
======================================================================
分班时： students 说 高一 ／ sc 说 高一
张三升到高二，只改了名册这一处（这是唯一正确的改法）：
   students 说 高二 ／ sc 说 高一  <- 假的
   而且 SQL 不会告诉你哪一份对：两份都是普通文本，谁也不指向谁

对照：绳子表只留两列（course_id, student_id），班级要用时现 JOIN 出来
   名册改完，JOIN 出来立刻是新的： [('张三', '高二', '语文')]
