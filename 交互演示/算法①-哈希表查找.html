算法模式 ① · 哈希表查找

例题：两数之和（LeetCode 1）· 阶段 A 主目标起步 · 本节讲清「暴力为什么慢 → 哈希怎么一次遍历解决」，含实测操作次数对比

① 题目（用数字数组，纯逻辑）

给一个整数数组和 一个目标值 target，找出两个不同位置的数，使它们的和等于 target，返回这两个位置的下标。

nums = [2, 7, 11, 15]   target = 9
答案：[0, 1]         # 因为 nums[0] + nums[1] = 2 + 7 = 9

# 换个更"像真实数据"的例子（比如你项目里各味药的用量数字）
nums = [3, 3, 4, 8]     target = 6
答案：[0, 1]
💡 为什么第 1 题永远是它：**它是"用哈希表把嵌套循环压成一层"的最小样板** —— 这个模式后面会反复出现（去重、分组、计数、看是否出现过）。

② 先看暴力法有多慢（先猜再看）

最直白的想法：把所有两两组合都试一遍。

for i in range(len(nums)):          # 第 1 个数的位置
    for j in range(i + 1, len(nums)):  # 第 2 个数（只往后找，避免重复配对）
        if nums[i] + nums[j] == target:
            return [i, j]
先猜：4 个数要比较几次？10 个数呢？
4 个数：组合数是 3+2+1 = 6 次；10 个数：9+8+…+1 = 45 次；n 个数：(n²-n)/2 次 → O(n²)

③ 关键洞察（一句话，整个模式的地基）

与其问"我和谁能凑成 target"，不如问"我需要谁，以及它出现过没有"。
你需要的那一个数 = target - 当前数。它唯一确定 —— 所以问题从"两两配对"变成了"查一个数在不在"。
动作暴力法哈希表法
问什么"你俩加起来是 target 吗""我需要的那个数出现过了吗"
要试多少次n(n-1)/2（两两组合）n（每个元素只看一次）
要额外空间吗不要要一个字典（记"见过的数和它的位置"）
💡 这和你在 SQL 里学的 JOIN ... ON id = outer_id 是同一个动作：拿一个值去另一张结构里换出对应的东西。哈希表就是"用值换值"的 O(1) 版本。

⑤ 能提交的完整代码（哈希表法）

def two_sum(nums, target):
    """返回两个加数为 target 的下标；没有就返回 []。时间 O(n)、空间 O(n)。"""
    seen = {}                        # 值 → 下标（"我见过这个数，它在第几号位置"）
    for i, x in enumerate(nums):
        need = target - x            # 关键：我需要的那一个数
        if need in seen:            # 先在"以前见过的"里找 → 保证下标不重复
            return [seen[need], i]
        seen[x] = i                  # 再把自己记下来，给后面的人用
    return []

print(two_sum([2, 7, 11, 15], 9))   # [0, 1]
print(two_sum([3, 3, 4, 8], 6))     # [0, 1]  ← 重复值也要对
⚠️ 顺序很关键：先"查 need"、再"存自己"。
如果反过来先存自己，当 target = 2*x 时会拿自己配自己（比如 [3,3], target=6 会返回 [0,0]）。

⑦ 同一个模式的变式（做完这题就能做这些）

题目把什么存进字典要额外注意什么
两数之和（本题）值 → 下标先查后存，避免自己配自己
看数组有没有重复元素值 → 出现过用 set 更省（只需"在不在"）
统计每个数出现几次值 → 次数d[x] = d.get(x, 0) + 1
字母异位词分组排序后的字符串 → 原词列表key 要能代表"同一组"
最长无重复子串字符 → 最近下标要配合"左边界"移动（滑动窗口）

⑧ 新手最容易错的 4 个点

错误症状 / 后果
先 seen[x] = i 再查 need返回 [0,0]（自己和自己配对）
返回 nums[i], nums[j]（值）题目要的是下标
忘记"无解返回什么"题目没明说就返回空列表，别让它报错
need in seen 写成 need in nums变成 O(n²)（每次都在列表里线性找），白学了
