算法模式 ② · 双指针

三个变式（有序数组两数之和 / 盛最多水 / 移动零）· 重点讲"为什么可以省掉一层循环"—— 那是这个模式的灵魂

① 先看清它和哈希表的分工（你已经会哈希表了）

模式靠什么省时间代价什么时候用
哈希表额外空间换查找 O(1)多花 O(n) 内存数据无序，只问"出现过没有/几次"
双指针数据有序（或能排序）换"一次决定排除一整片"常常要先排序（O(n log n)）数组有序，或"两头往中间逼"的问题
一句话记：哈希表是"记住见过什么"，双指针是"利用排好的顺序"。
题目给了有序数组 → 先想双指针；题目没序、只问存在性 → 先想哈希表。

② 灵魂：一次比较，为什么能"排除一整片"

问题：有序数组里找两个数加起来等于 target。

nums = [1, 3, 4, 6, 8, 11]      target = 10
         ↑                 ↑
         L                 R

L=1, R=11 → 和 = 12 > 10  →  太大了
关键推理：既然 1 + 11 都太大了，那么 1 和任何其他数相加都更大（因为其他数都比 11 小吗？不 —— 是比 11 小，所以和更小…）
⚠️ 上面那句是故意写错的。你自己推一遍：R 指向的是当前最大的数。
若 nums[L] + nums[R] > target，说明 nums[R] 和谁都太大了（L 已经是最小端）→ R 可以整个排除，R--。
✅ 正确推理：
· 和 > target → R 太大 → R -= 1（L 已经是最小的了，配 R 都不行，R 跟谁都不行）
· 和 < target → L 太小 → L += 1
· 和 == target → 找到
每一步都"永远排除掉一个元素"，所以最多走 n 步 → O(n)。这就是它比暴力 O(n²) 快的根本原因。

④ 能提交的完整代码（有序数组两数之和）

def two_sum_sorted(nums, target):
    """有序数组里找两个数之和 = target，返回下标 [i, j]；没有返回 []。时间 O(n)、空间 O(1)。"""
    L, R = 0, len(nums) - 1
    while L < R:                       # 注意是 < 不是 <=：不能自己和自己配
        s = nums[L] + nums[R]
        if s == target:
            return [L, R]
        elif s > target:
            R -= 1                       # 太大了 → 右指针往左
        else:
            L += 1                       # 太小了 → 左指针往右
    return []

print(two_sum_sorted([1, 3, 4, 6, 8, 11], 10))   # [2, 3] → 4+6=10
💡 和哈希表版对比：哈希表版不需要有序（空间 O(n)），双指针版要求有序但只用 O(1) 额外空间。
面试里如果数组已排序，说双指针更加分；没排序就要先说"排序会破坏原下标"这个坑。

⑤ 同模式三变式（同一个骨架，换判定条件）

题目指针怎么动要额外维护什么
有序两数之和和大了 R--，和小了 L++没有（最简单）
盛最多水的容器每次移动较矮的那一边（移动高的必然变小）维护"目前最大面积"
移动零（原地）两个都从左边出发：一个找非零、一个放位置要交换（原地改写）
盛水题的关键推理（自己过一遍）：面积 = 宽 × 较矮的高度。
往中间收，宽度一定变小 → 只有"增高"才可能让面积变大 → 所以只能舍掉矮的那根并赌后面有更高的。
# 盛最多水（骨架同，只是判定换成"面积"）
def max_area(h):
    L, R, best = 0, len(h) - 1, 0
    while L < R:
        best = max(best, (R - L) * min(h[L], h[R]))
        if h[L] < h[R]:
            L += 1
        else:
            R -= 1
    return best

# 移动零（双指针的另一种形态：同向、不等速）
def move_zeroes(nums):
    pos = 0                          # pos = 下一个"非零数该放的位置"
    for i in range(len(nums)):
        if nums[i] != 0:
            nums[pos], nums[i] = nums[i], nums[pos]

⑥ 最容易错的 5 个点

错误后果
while L <= R同一个元素自己配自己（两数之和类题目）
数组没序就上双指针判定失效，答案随机
盛水题移动较高的那边漏掉最优解（高度只可能更矮）
忘了返回原下标 vs 排序后下标题目要原下标时，排序后必须另存映射
移动零里用 append/remove 新建列表题目要求"原地"，且复杂度可能退化
