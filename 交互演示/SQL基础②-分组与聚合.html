SQL 基础 ② · 分组与聚合

把"很多行"压缩成"每类一行" —— GROUP BY / HAVING / COUNT/SUM/AVG/MAX/MIN。示例数据是上一张的 learners 表。

① 先说它解决什么问题

上一张的查询是一行进、一行出：查明细。

但老板问的是这种问题：

  • 「一共有多少人？」→ 不是某个人的信息，是整个表的总结
  • 「每个城市各有多少人？」→ 不是一行，而是每个城市一行
  • 「大家平均几岁？」→ 一堆数字压成一个
这类"把多行压成一行（或每类一行）"的活儿，就叫聚合。它的搭档是 GROUP BY。

② 五个聚合函数（参数种类 + 返回类型）

函数签名返回类型干什么 / 坑
COUNT(*)COUNT(*)int数行数（含 NULL 的行也算）
COUNT(列)COUNT(col)int数这一列非 NULL 的个数 —— 和 COUNT(*) 结果常不一样！
SUMSUM(col)数字求和，跳过 NULL
AVGAVG(col)float平均值，分母不含 NULL 行（最容易算错的地方）
MAX/MINMAX(col)该列类型最大/最小，跳过 NULL
💡 记忆：COUNT(*) 数行，COUNT(列) 数"填了值的"。表里 6 行、其中 1 行 age 是 NULL，那么 COUNT(*)=6 而 COUNT(age)=5。

③ GROUP BY 到底做了什么（抽丝剥茧）

数据（6 行，city 有一行是 NULL）：小明/合肥、小红/合肥、小刚/芜湖、小美/NULL、阿强/芜湖、小雨/合肥
SELECT city, COUNT(*)
FROM learners
GROUP BY city;
① 分组：按 city 的值，把行分堆（相同的放一堆）
堆堆里的行COUNT(*)
合肥小明(19) · 小红(20) · 小雨(22)3
芜湖小刚(NULL) · 阿强(19)2
NULL小美(21) —— NULL 自己算一堆1
② 每堆算一个值：对每一堆分别算 COUNT/SUM/AVG…（不是整表一起算）
③ 每堆输出一行：所以结果是 3 行，不是 6 行
⚠️ 真实结果就是 3 行：合肥 3、芜湖 2、NULL 1。这就是"多行压成每类一行"。

④ 分组后，SELECT 里能写什么（铁律）

只能写两类东西：① GROUP BY 里出现过的列 ② 聚合函数
写法行不行为什么
SELECT city, COUNT(*) … GROUP BY city✅city 是分组依据，每堆一个值
SELECT name, COUNT(*) … GROUP BY city❌一堆里有 3 个 name，缩不成一个 —— 数据库不知道给你哪个
SELECT city, AVG(age) … GROUP BY city✅聚合函数会把一堆压成一个值
SELECT COUNT(*) FROM learners✅不写 GROUP BY = 整表当一堆 → 结果 1 行

⑤ WHERE 和 HAVING：都叫筛选，筛的东西不同

WHEREHAVING
筛什么行组（分组之后的结果）
什么时候执行分组之前分组之后
能用聚合吗不能能
例子WHERE age > 18HAVING COUNT(*) >= 3
实测报错（SQLite）：SELECT category, COUNT(*) FROM prescriptions WHERE COUNT(*)>1 GROUP BY category;
→ OperationalError: misuse of aggregate: COUNT()（"聚合用错地方了"）
💡 老板问"人数 ≥3 的城市" → GROUP BY city HAVING COUNT(*) >= 3，不是 WHERE。

⑥ 完整的执行顺序（本张卡最重要的一张图）

写的时候是这个顺序 ↓

SELECT … FROM … WHERE … GROUP BY … HAVING … ORDER BY … LIMIT

数据库真正执行是这个顺序 ↓

① FROM  找表
② WHERE 筛行（不要的行先扔掉）
③ GROUP BY 分堆
④ HAVING 筛组（不要的堆扔掉）
⑤ SELECT 挑列 / 算聚合
⑥ ORDER BY 排序
⑦ LIMIT  截断
看懂这个顺序，⑤ 的疑问就自动解开了：WHERE 在第 ② 步，那时还没分堆，怎么可能用聚合？

⑧ 换到你的真实库（实测数字）




-- 每类方剂有几首（实测：5 组）
SELECT category, COUNT(*) FROM prescriptions GROUP BY category ORDER BY COUNT(*) DESC;
-- → 解表剂 3 · 补益剂 2 · 祛湿剂 1 · 清热剂 1 · 和解剂 1

-- 药材 ≥5 味的方剂（WHERE 不行，必须 HAVING）—— 实测 4 首
SELECT p.name, COUNT(pi.ingredient_id) c
FROM prescriptions p
JOIN prescription_ingredients pi ON p.id = pi.prescription_id
GROUP BY p.id
HAVING c >= 5
ORDER BY c DESC;
-- → 藿香正气散 12 · 银翘散 9 · 小柴胡汤 7 · 桂枝汤 5
