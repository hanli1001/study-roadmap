值得做真卡片grep按「内容」找东西

今天任务 2 就要用。它是 参数最多、最容易拼错的一个 —— 而且有个真坑下面会讲。

$ grep "8009" .
左边勾一个，上面这行就是你要敲的完整命令。
⚠️ 真坑：grep 默认是「子串匹配」，不是「找这个词」

实测（我在本机真跑的）：一个文件里有两行 ——

1  端口 8009 在监听
2  颜色值 0.800927443 是小数
$ grep -c "8009" 文件        →  2      ← 小数里的 8009 也被算进来了
$ grep -cw "8009" 文件       →  1      ← 加了 -w，只剩真端口

🔑 这跟我们修过的两个 bug 是同一类：导师那份示例代码里的 "助餐" in "助餐,健康监测"、还有卡片校验器的 /on/ 把 persons 误判。 「包含」不等于「是」 —— 找的时候想一下：我要的是子串还是整词？

⚠️ 另一个真坑：-r 会钻进 .venv / node_modules

实测：在本机项目里搜 8009，8 条命中全来自依赖目录，一条有用的都没有。

$ grep -rn "8009" --include="*.py" .                    →  8 条，全是 .venv 里的噪音
$ grep -rn "8009" --include="*.py" --exclude-dir=.venv .  →  0 条（干净了）

你服务器上对应的是 .venv / node_modules / .git —— 搜之前先把它们排掉。

看一眼就懂find / locate按「名字」找东西

跟 grep 是两个不同的问法：find 按名字，grep 按内容。别混。

写法意思 / 坑
find / -name "api.py"从根目录按名字找。慢，且会刷一堆没权限的报错 → 尾巴加 2>/dev/null
locate api.py走数据库，快得多；但刚建的文件可能还没索引，找不到不代表没有
值得做真卡片2>/dev/null把「报错」扔掉

今天任务 1、2 都会看到它。不理解它会以为命令写错了。

写法意思
命令 > 文件把正常输出写进文件（1 号口）
命令 2> 文件把报错写进文件（2 号口）
命令 2>/dev/null把报错扔进黑洞（/dev/null = 垃圾桶）
命令 > f 2>&1正常和报错都收进同一个文件（cron 里必写）

实测对照：不带重定向时屏幕刷 grep: /root: No such file or directory；加上 2>/dev/null 之后干干净净什么都不显示。

迷你课 1 最值钱的一个符号。理解了它，你就能把小命令拼成大工具。

$ grep -rn "sqlite3" --include="*.py" . | wc -l

符号意思
A | B管道：A 的输出 → 变成 B 的输入
A > f写入文件（会覆盖！先把原文件 cp 备份）
A >> f追加到末尾（安全）
$(命令)把命令的输出当值用，例：N=$(ls | wc -l)
值得做真卡片du -sh */ | sort -rh | head任务 5 · 谁占地方

三个命令拼起来才解决问题 —— 正好是上一张卡片的实战。

$ du -sh */ | sort -rh | head -4
500M    _ref/          ← du -sh */  每个目录有多大
3.9M    打印资料/       ← sort -rh   按体积从大到小排
3.5M    交互演示/       ← head -4    只看前 4 个
212K    rag/
拆开看各干什么
du -sh */算每个子目录的总大小（-s 只要总数，-h 人类可读）
sort -rh-h 让它看得懂 M/G（不然 500M 会被当成字符串排在 3.9M 前面）
df -h整个磁盘还剩多少 —— 和 du 不是一回事

四、第 3 课 + D8 作业：会敲到的

值得做真卡片sqlite3 四步有过程 / 有状态 → 够格

D8 作业你要自己建三张表 —— 一定会敲到这四步。顺序错了就报错。

import sqlite3
conn = sqlite3.connect("demo.db")     # ① 连上（文件不存在会自动建）
cur  = conn.cursor()                  # ② 拿一个游标（真正干活的是它）
cur.executescript("""CREATE TABLE ...; INSERT ...;""")   # ③ 执行
conn.commit()                         # ④ 提交！忘了这句 = 白干
conn.close()                          # ⑤ 关上（跟 conn.close() 漏写那个坑一样）
函数返回什么 / 坑
sqlite3.connect(path)返回 Connection。用 ":memory:" 是内存库，跑完就没，不污染文件
conn.cursor()返回 Cursor。查询结果都从它身上拿
cur.execute(sql)返回 游标本身（可以链式调）；不是结果
cur.fetchall()返回列表，每个元素是一个 tuple（一行）
cur.fetchone()返回一个 tuple；没数据了返回 None
conn.commit()写操作不 commit = 没生效。这是最常见的"我明明插进去了啊"
看一眼就懂JOIN / LEFT JOIN / COUNT第 3 课正课

这几条有专门的交互卡（交互演示/SQL基础③-JOIN详解.html），上课时我会带你推。

写法一句话
JOIN 表B ON A.id = B.a_id只留两边都配得上的行。查出来是空 → 先怀疑 ON，别怀疑数据没了
LEFT JOIN左边的表一行都不能丢，配不上的填 NULL
COUNT(列)数这一列非 NULL 的行数 —— 和 COUNT(*) 不一样
GROUP BY 列按这列分堆，每堆算一次聚合

五、LeetCode 地板：模式③ 滑动窗口

值得做真卡片float("inf")为什么用它当"最大"

滑动窗口求"最短"时几乎必用。乍看很怪，理解了就一句话。

best = float("inf")        # 一开始没有任何答案 → 先设成"无穷大"
for ...:
    best = min(best, 当前长度)   # 任何真实长度都比它小，第一轮就能被替换掉
print(best)                # 如果还是 inf → 说明压根没找到答案（这是个有用的信号）
写法类型 / 坑
float("inf")类型是 float。比任何数值都大，但不是整数
-float("inf")求"最大"时当初始值
反过来的坑求最大值时初始设 0 → 全是负数就全错（这跟模式②里你用 max 当水位那个坑是同一类）
