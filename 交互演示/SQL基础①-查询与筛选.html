① 一条查询的骨架：它为什么长这样

SELECT   要看的列          ← 我要什么
FROM     哪张表            ← 从哪拿
WHERE    行的条件          ← 只要哪些行
ORDER BY 按什么排          ← 怎么排
LIMIT    最多几条          ← 要几条
子句人话必需？不写会怎样
SELECT要哪些列必需少了它就不是查询
FROM从哪张表必需不知道去哪找数据
WHERE筛选行可选全都要
ORDER BY排序可选顺序由数据库随便定（不保证，要顺序就得写）
LIMIT取前几条可选全给
💡 书写顺序就是上面这个顺序，不能乱；但数据库执行顺序是 FROM → WHERE → SELECT → ORDER BY → LIMIT（先找到表、再筛行、再挑列、再排序、最后截断）。这个区别是理解 SQL 的关键。

② 取列：* 是什么意思

写法结果
SELECT * FROM learners;所有列（* = "全部列"，星号是通配符）
SELECT name FROM learners;只要 name 一列
SELECT name, age FROM learners;两列，顺序按你写的来（不是表的顺序）
SELECT name AS 姓名 FROM learners;给列起别名，结果显示叫「姓名」
⚠️ 实战里少用 *：列一多就浪费；别人改表结构你会被动跟着变。写清要哪几列。

④ NULL：它不是 0，也不是空字符串（最容易踩的坑）

写法结果为什么
WHERE age = NULL0 行 ❌NULL 不等于任何东西，连它自己都不等于。比较结果是"未知"，永远不成立
WHERE age IS NULL1 行 ✅判断"是不是空的"必须用 IS NULL
WHERE age != 193 行年龄 20/21/22（小刚的 NULL 不算进来 —— 未知的东西不满足任何条件）
WHERE age > 184 行19/20/19/22，NULL 被排除
age + 1NULL任何值和 NULL 做运算 → 还是 NULL
💡 一句话：NULL = "不知道"。你不知道小刚几岁，所以"小刚 < 20 岁吗"的答案是"不知道"，不是"是"也不是"不是"。

⑤ 排序：ORDER BY 的三种花样

写法结果
ORDER BY age升序（小到大）。默认 ASC
ORDER BY age DESC降序（大到小）
ORDER BY city, age DESC先按城市，城市相同的再按年龄降序（多级排序）
ORDER BY age（含 NULL）SQLite 里 NULL 排最前；想控制用 NULLS LAST（不是所有数据库都支持）
⚠️ 不写 ORDER BY，数据库返回顺序不保证。今天看着有顺序，明天换个版本可能就变了 —— 要顺序就显式写。

⑥ 限制条数：LIMIT / OFFSET

写法结果
LIMIT 2只要前 2 条
LIMIT 2 OFFSET 1跳过第 1 条，再取 2 条（= 第 2、3 条）
ORDER BY age DESC LIMIT 1"最大的那个" —— 配合排序才能当"取第一名"用
💡 分页就是 LIMIT 每页条数 OFFSET (页号-1)*每页条数。
