先猜，再看答案

先猜不是走流程 —— 猜错反而记得更牢（回忆失败本身就有用）。答案先别给。

这三个空，你先填一遍再往下看：

SELECT persons.name
FROM   ______                                  -- ① 起点：我要查"几号群"，站哪张表？
JOIN   ______ ON ______ = ______               -- ② 拿群 id 去绳子表配对
JOIN   ______ ON ______ = ______               -- ③ 绳子上的 uid，去哪张表换名字？
WHERE  ______;                                 -- ④ 只要 1 号群
空答案为什么
①groups我要查"几号群"，主干就是群表
②group_members ON groups.id = group_members.gid拿群 id 去绳子表配 gid
③persons ON group_members.uid = persons.id绳子上的 uid 去人表换名字
④groups.id = 1没这一句，你会得到所有群的所有成员

实测：不写 ④ → 出 3 行；补上 ④ → 出 2 行。差的这一行就是"筛选"和"配对"的区别。

卡问答

      
        
概念什么是"绳子表"？为什么多对多必须用它？一行 = 一条关系，不是一个人；名字会变会重复，所以只存 id

        
预测三表 JOIN 不加 WHERE 会出几行？= 绳子表的行数（配对成功的次数），不是某张表的行数

        
找错ON groups.id = group_members.uid 错在哪？群 id 对人 id，两头接反 → 0 行不报错；id 重叠时还会返回"看着合理"的假数据
