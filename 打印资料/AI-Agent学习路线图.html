⑤ 三条实话（省得你走弯路）

1. 这本书不是入门教材，别想着按顺序啃完。
正文约 50 万字 + 109 个实验。官方"入门级"是相对有编程基础的人说的。
正确用法：当成项目库 + 字典 —— 卡在哪查哪，想做什么找对应实验。
2. 作者明说：配套代码不用逐行读。
原话：「本书的配套代码全部由 coding agent 根据书稿生成，作者也不会逐行阅读。关键是把架构、核心组件和设计原则想清楚，然后让 AI 去写代码……」
—— 这条对你是好消息：你现在的学法（我写你验 / 你写我审）本来就对路。
3. 第 8 章直接跳过。
全书唯一需要机器学习与模型训练经验的一章；而且你这台机器 8G 显存做不了训练，投入产出比为零。

Ollama 默认给模型开 32768 的上下文，KV cache 白吃一大片显存。
实测后果：跑几十次后 runner 直接崩，报 model runner has unexpectedly stopped； 崩了之后模型还会继续"回答"，但全是垃圾（每道题都答 23）—— 假数据比报错危险。
解法：请求里加 "num_ctx": 4096。加了之后 30 次突发调用零失败。

⑦ 两个必须知道的坑（我都实测撞过）

坑 1 · 书上 --provider ollama 在 Windows 上开箱即坏
注册表把 ollama 的地址写死成 http://localhost:11434/v1。
但本机 localhost 解析到 IPv6 ::1，而 Ollama 的 /v1 在 ::1 上直接断开连接 （WinError 10054 / APIConnectionError）。
解法：跑之前设环境变量
OLLAMA_BASE_URL=http://127.0.0.1:11434/v1
（curl http://localhost:11434/v1/models 返回 200，所以很容易误判成"服务没问题"—— 但 curl 和 httpx 的解析路径不一样，别用 curl 的结果给 SDK 背书）
坑 2 · 书里有个 bug，会把真错误藏起来
chapter1/context/agent.py 只写了 from openai import OpenAI， 没有 import openai，但异常处理里用了 openai.APITimeoutError → 一旦 API 出错，异常处理器自己先崩，你看到的是 NameError: name 'openai' is not defined， 真正的错误信息（上面那条 IPv6 连接失败）被完全掩盖。
我从 _ref/ 的本地副本加了这一行（原仓库未改），加完才看到真错误。
