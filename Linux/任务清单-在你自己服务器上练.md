## ⚠️ 先看这个：危险命令清单（比学什么更重要）

**在真机上，下面这些一条敲错就可能回不来。练之前先把这张表记住。**

| 命令 | 危险在哪 | 安全替代 |
|------|----------|----------|
| `rm -rf /` 或 `rm -rf *` | **删库跑路**，且 Linux 没有回收站 | 先用 `ls` 看要删什么，再 `rm` 加具体路径 |
| `rm -rf $VAR/`（变量为空） | 变量没值时变成 `rm -rf /` | 用 `rm -rf "${VAR:?}"` —— `:?` 让空值直接报错 |
| `> 文件`（重定向到已存在的文件） | **直接清空原文件**，没有确认 | 先 `cp 文件 文件.bak` |
| `kill -9 <PID>` | 强杀，进程没机会存盘/关连接 | 先 `kill <PID>`（温和），等 5 秒再说 |
| `chmod -R 777 .` | 把整个目录开成谁都能改 | 只用 `chmod +x 某个脚本` |
| `docker rm -f $(docker ps -q)` | 删掉**所有**容器 | 先 `docker ps` 看清楚，再指定名字 |
| `apt install` 输错源 | 可能把依赖搞乱 | 不确定就别装 |

> 🔑 **一条铁律**：**不确定的命令，先在 `--help` 或空跑一遍。**
> 这跟你写代码前的「静态三查」是同一个习惯 —— 只不过这里查的是"这条命令会改什么"。

## 开工前 5 分钟：`sudo` 是什么（你会一直用到它）

> **2026-10-06 学员问「sudo 是什么命令」时补的** ——
> 这份材料里用了 **11 次 `sudo`，却从没解释过它**。又一次"我把没教过的词当成他已经知道的"。

**一句话（这是 Linux 自己给的说法）**：

```bash
whatis sudo
# sudo (8)  - execute a command as another user      ← 以另一个用户的身份执行一条命令
```

### 为什么需要它

Linux 里有一个**超级用户 `root`** —— 它能改系统里的**任何东西**（包括把系统本身删掉）。
所以规矩是：**平时用普通用户干活**（你就是 `ubuntu`），**只在真需要的时候临时借一次** root 权限。
`sudo` 就是那一次「借」。

### 只有三个概念

| 概念 | 意思 |
|------|------|
| **`root`** | 超级用户，能改任何东西。**不要一直用它干活** |
| **`sudo 命令`** | 就这**一条**命令以 root 身份跑，跑完权限**立刻还回去** |
| **`sudo -l`** | 看**我**能 sudo 什么（最该记住的一条，卡住时先跑它） |

> **`sudo` 和 `su` 的区别**（名字像，别混）：
> `su` = **换身份**（开一个 root 的 shell，你**一直待在里面**）→ 危险、容易忘记自己在 root 里；
> `sudo` = **只借一条命令** → 安全，是现在的主流做法。

### 你的机器上是什么情况（2026-10-06 实测）

```bash
sudo -l
# Matching Defaults entries for ubuntu on 10-7-150-148:
#     env_reset, mail_badpass, secure_path=..., use_pty
# User ubuntu may run the following commands on 10-7-150-148:
#     (ALL : ALL) ALL
#     (ALL) NOPASSWD: ALL        ← 注意这个 NOPASSWD
```

**`NOPASSWD` = 你不用输密码。** 为什么？因为云服务商装机时替你写了这一行：

```
/etc/sudoers.d/90-cloud-init-users:4:  ubuntu ALL=(ALL) NOPASSWD:ALL
```

⇒ 所以**你的 `sudo` 敲下去就直接执行**。（在别人的机器上，通常会先问你要密码。）
另外你也在 **`sudo` 组**里（`groups` 实测：`ubuntu adm cdrom sudo dip lxd docker`）。

### 🔬 30 秒自己验一遍：「**借**」和「**拥有**」的区别

> 2026-10-06 学员答「主人是服务器，**我是管理者、超级用户**，可以读取显示pid」时补的 ——
> **结论对（加 sudo 确实读到了 pid），但两个角色都反了**，而且他描述的是 **`su` 的模型，不是 `sudo` 的**。
> 这个区别**不是文字游戏** —— 想错的人会以为"sudo 过了我就是 root 了"，于是对后面的命令失去警惕。

```bash
id          # uid=1000(ubuntu) gid=1000(ubuntu) groups=...   ← 你
sudo id     # uid=0(root)     gid=0(root)     groups=...     ← 借来的（只有这一条命令）
id          # uid=1000(ubuntu) gid=1000(ubuntu) groups=...   ← 立刻打回原形
```

**最后那次 `id` 才是重点** —— 它证明 `sudo` **没有**把你变成 root，
它只是**替你向 root 借了那一条命令的权限**，用完就还。

**比喻**：`sudo` 不是「你拿到了管理员门卡」，而是「**保安替你刷了一次门**」。
下一条命令你没写 `sudo`，门就还是关的。

**那进程的主人是谁？**（同一台机器实测）

```bash
ps -o pid,user,comm -p 1399846,1399877,1399883
# 1399846 root     uvicorn
# 1399877 root     docker-proxy      ← 主人是 root（一个【用户】）
# 1399883 root     docker-proxy
```
⇒ **主人是 `root` 这个用户，不是「服务器」。**
**进程的主人是「人（用户）」，不是「机器」。** 说"服务器拥有这个进程"没法回答"那我为什么读不了"。

### 🔑 所以「不加 sudo 就没有 pid」的完整链条

```
ss -p 要显示 pid
   ↓ 它得去读那个进程的信息
实际读的是  /proc/<pid>/fd          ← 谁建的？root
   ↓
实测：ls -ld /proc/1399877/fd
      → Permission denied           ← 你（ubuntu, uid=1000）读不了
   ↓
ss 不报错，只是【沉默地少显示一栏】
```

**这不是 `ss` 的 bug，是权限在起作用 —— 而且它表现成「少了一栏」，不是「报错」。**
⇒ 这就是为什么「**没显示**」和「**不存在**」必须分开对待。

### ⚠️ 但「不用密码」意味着「没有刹车」

`sudo` 后面接什么，就**以 root 身份执行什么**：

- **它不会问你「确定吗」** —— 它只管执行
- 危险的不是 `sudo` 本身，是**你在 `sudo` 后面敲了什么**
- 所以：**敲 `sudo` 之前先停半秒，把命令在脑子里跑一遍**
  （这也是本页最上面那张危险命令清单要你先看的原因）

# 微课 1 · 找到东西（预计 20 分钟）

### 任务 1 · 先搞清楚"我在哪"

**目标**：登进服务器后，回答三个问题 —— 我在哪个目录？这个目录里有什么（**包括隐藏文件**）？我的家目录在哪？

**验证**：把你的答案和下面三条命令的输出对照
```bash
pwd            # 我在哪（print working directory）
ls -la         # 这个目录里有什么，-a 才会显示 . 开头的隐藏文件
echo ~ && cd ~ && pwd   # ~ 是家目录，cd 过去再看一次
```

**提示**：`ls` 不带 `-a` 时**看不到 `.env`、`.git` 这类文件** —— 而你的项目里恰恰有 `.env`。

<details><summary>答案</summary>

```bash
pwd                 # 实测：/home/ubuntu（你的用户名是 ubuntu，所以家目录不是 /root）
ls -la              # 会看到 . 和 .. 和隐藏文件（.bashrc / .git / .env 这类）
cd ~ && pwd         # 实测：/home/ubuntu —— ~ 展开成家目录
```
**概念**：`~` 是 shell 帮你展开的**家目录缩写**（谁的家？**当前登录用户的家**）；
`.` 是当前目录，`..` 是上一级。
</details>

### 任务 2 · 找到你的项目在哪

**目标**：不知道项目放哪了 —— 用命令把它找出来。

**验证**：找到后 `cd` 进去，`ls -la` 能看到 **`api.py` 和 `prescription_db.py`**，并且目录里有 **`.git`**。

> 🔴 **两条"看起来该有、其实没有"的坑（2026-10-05 实测，别拿它们当判据）**：
> - **`docker-compose.yml` 不在这个项目里** —— 它属于另一个项目（`~/openclaw-cn/`）。按它找会以为"我没这个文件"。
> - **这台机器没装 `locate`** —— 用它按名字查会直接报 `command not found`（想用得先 `sudo apt install mlocate`）。

**提示**：两个方向 —— 按**文件名**找，或按**内容**找。

> ⚠️ **按名字找会淹你一脸**：这台机器上叫 `api.py` 的文件有 **77 个**（几乎全是 Python 库自带的），**属于你的只有一行**。
> 翻不到底就换成"按内容找" —— 快、准，而且那是更该会的问法。

<details><summary>答案</summary>

```bash
# ① 按名字找 —— 实测刷出 77 条，你的在最后
find / -name "api.py" 2>/dev/null

# ② 只留你自己的：把系统目录筛掉（实测只剩 1 条）
find / -name "api.py" -not -path "/usr/*" -not -path "/snap/*" \
     -not -path "*/site-packages/*" -not -path "*/extensions/*" 2>/dev/null

# ③ 按内容找（推荐）：哪些 .py 里写了「方剂」—— 实测 2 条，两条都是你的
grep -rln "方剂" --include="*.py" /home/ubuntu 2>/dev/null

# ④ 找到之后进去看一眼
cd /home/ubuntu/study-roadmap && ls -la

# ⑤ 顺手确认"它活着"（这是任务 6–9 的正题，这里先尝一口）
curl -s -o /dev/null -w "%{http_code}\n" localhost:8009/docs
#   200  ← 服务在跑。也可以直接开浏览器看 http://123.58.220.17:8009/docs
```
**概念**：`find` 按名字/时间/大小找，`grep` 按内容找 —— **两个不同的问法，别混**。
**为什么推荐 ③**：`find` 问的是"**叫什么名字**"，`grep` 问的是"**里面写了什么**"。
你不记得文件叫什么，但记得它是干什么的 —— 那就该用 `grep`。

> ⚠️ **找到项目之后最常见的两个误判**（2026-10-05 学员真实踩到）：
> ① **`python api.py` 报"没有 fastapi"** ⇒ 不是项目坏了，是**依赖装在容器里、不在宿主上**（见上面〈补课 · Docker 是什么〉）
> ② **"我得先启动它"** ⇒ 它**已经在跑**（那个 200 就是证据）—— 你要学的是**怎么看它**，不是怎么点着它
</details>

### 任务 3 · 看文件，但别用 `cat`

**素材**：这台机器上现成的、**而且正在被写入**的日志 = **`/var/log/syslog`**（实测 **21,235 行**）。

> ✅ **你能读它** —— 你的账号 `ubuntu` 在 **`adm` 组**里，而 syslog 的属组就是 `adm`。
> ⚠️ 这一节原来写的是 **`app.log`** —— **那个文件根本不存在**（2026-10-05 实测：项目目录、整个家目录都没有）。
> 又一次"我假设你有某个文件"。

**目标**：① 看它有多少行 ② 看最后 20 行 ③ **实时**看新写入的行

**验证**：三条都跑出来；第三条要能看到新内容**自己冒出来**（再开一个终端制造点流量）

**提示**：`cat` 会把整个文件吐到屏幕上 —— 大文件会把终端卡死。

<details><summary>答案</summary>

```bash
wc -l /var/log/syslog        # ① 行数（word count -l = lines）—— 实测 21235
tail -20 /var/log/syslog     # ② 最后 20 行 —— 实测能看到 CRON[...] / node[...] 这类行
tail -f /var/log/syslog      # ③ -f = follow，实时跟踪。Ctrl+C 退出
```
**概念**：看文件的三件工具分工 ——
`cat` 看小文件 ｜ `less` 翻大文件（`q` 退出）｜ `tail` 看末尾、`-f` 追新行。
**排查问题 90% 的时候你要的是 `tail -f`。**

🔑 **但最该练的 `-f` 是你自己的服务**（因为新日志**你能自己制造**，一眼就看出效果）：

```bash
# 终端 A：盯着你自己的方剂 API
docker logs -f fangji-api

# 终端 B：随便请求它一下
curl -s -o /dev/null localhost:8009/docs

# ⇒ 终端 A 里立刻冒出一行：
#   INFO:  172.17.0.1:xxxxx - "GET /docs HTTP/1.1" 200 OK
```
**这才是"实时日志"在实际工作里的样子** —— 你改一行、请求一次，就看着它滚出来。
</details>

### 任务 4 · 把命令的输出来回倒腾（管道）

**素材**：还是 `/var/log/syslog`

**目标**：**只看含某个关键词的行，并且只数有多少条**。

**验证**：屏幕上只出现一个数字

**提示**：两条命令用 `|` 接起来 —— 前一条的输出，变成后一条的输入。

<details><summary>答案</summary>

```bash
grep CRON /var/log/syslog | wc -l    # 筛出 CRON 行 → 数行数。实测 3063
```

> ⚠️ **原例写的是 `grep ERROR app.log` —— 但这台机器上 `ERROR` 一条都没有**（实测 **0 行**）。
> **`0` 也是一个真实答案**：说明这个日志里没人报错。
> **"查不到"和"坏了"是两件事** —— 先分清，再动手。

🔑 **顺手学一个真坑：`grep` 默认区分大小写。** 同一台机器、同一个词，实测：

| 命令 | 结果 |
|------|:----:|
| `grep -c ERROR /var/log/syslog` | **0** |
| `grep -c error /var/log/syslog` | **3** |

**只差大小写 —— 一个"一条都没有"，一个有 3 条。**
⇒ **查不到东西的时候，第一件事先想想大小写。**（`-c` = 只输出条数；`-i` = 忽略大小写）

```bash
# 变式：先筛再存，然后慢慢看（写在你自己的家目录，随便造）
grep CRON /var/log/syslog > cron.txt
wc -l cron.txt
```
**概念**：`|`（管道）= **把左边命令的输出，接到右边命令的输入**。
这是 Linux 最值钱的一个符号 —— 小命令拼起来能干大事。
`>` 是**写入文件**（会覆盖！），`>>` 是**追加**。
</details>

### 任务 5 · 磁盘满了？先找出谁占地方

**目标**：服务器提示磁盘满，找出**占空间最大的 3 个目录**。

**验证**：输出 3 行，按大小从大到小排

**提示**：`du`（disk usage）算体积，`sort -rh` 按人类可读的大小**倒序**排。

<details><summary>答案</summary>

```bash
du -sh */ | sort -rh | head -3      # 当前目录下各子目录的体积，取前 3
df -h                                # 顺便看整个磁盘还剩多少
```
**实测（2026-10-05，在 `/home/ubuntu` 下跑）—— 这就是你该看到的形状：**
```
248M  openclaw-cn/
205M  learn/
 72M  azyd-forum/
```
```
/dev/vda1   77G  27G  50G  35%  /        ← df -h 的最后一行
```

**概念**：`-h` = human readable（显示成 1.2G 而不是 1234567）；
`-r` = reverse（倒序），`sort -h` 才能正确比较 `9M` 和 `1.2G`。
**⚠️ `du -sh */` 只扫当前目录一层**，要往下钻就 `cd` 进最大的那个再跑一次。

> 💡 **这题为什么值钱**：磁盘满是最常见的"服务器突然不干活了"的原因。
> 而 `du -sh */ | sort -rh | head -3` 是**一条命令把"谁占地方"排出来** ——
> 你自己拼出来的（`du` + `|` + `sort` + `|` + `head`），四个零件，全都见过。
</details>

## 补课 · Docker 是什么（10 分钟，用你自己的项目讲）

> 这一节不是额外的任务，是**补一个洞**。你服务器上的方剂 API 就是 Docker 跑的，
> 所以下面每一个数字都是**从你那台机器上实测出来的**。

### 要解决的是这个问题

你在本机写好了 `api.py`，怎么让它在你服务器上也能跑？传统办法是**到服务器上再装一遍**：
装 Python 3.12、装 fastapi、装 uvicorn、配环境变量……然后某天服务器上的 Python 升了个级，
你的程序就崩了 —— 这就是那句名言：**"在我机器上明明能跑"**。

**Docker 的办法：把"你的代码"和"它需要的整个运行环境"一起打包**，变成一张**安装盘**。
拿到哪台机器上，跑起来都跟在你本机一模一样。

### 只有三个词（就这三个）

| 词 | 是什么 | 生活里的类比 | 你的服务器上 |
|----|--------|-------------|-------------|
| **镜像**（image） | 打包好的"安装盘"：代码 + Python + 依赖，全在里面 | 一张**光盘** | `prescription-api:latest`（**245 MB**，2 个月前做的） |
| **容器**（container） | 从镜像**跑起来的一份**。同一张盘能跑很多份，互不干扰 | 光盘**放进光驱跑起来**的那一次 | `fangji-api`（正在跑） |

### 🔑 再掰开一个概念：`docker` 其实是**两半**

> 这是 2026-10-05 学员问「**我怎么在 Linux 里运行 docker**」时补的。

> `ss` 要加 sudo 而这个不用 —— **不同的门，不同的钥匙**。）

### 🔴 顺带把任务 8 那个"二选一"说清楚：**答案是"两个都有，但在不同层"**

任务 8 问「你的服务是用 **systemd** 管的，还是 **docker** 跑的」——
实测你的情况是**两层叠加**：

```
第 1 层：systemd  管着  docker.service（dockerd 这个后台程序）
第 2 层：dockerd  管着  你的容器 fangji-api（里面跑着你的方剂 API）
                            ↑ 你的应用在这一层
```

⇒ **你的应用是 docker 跑的**（所以重启要用 `docker restart fangji-api`，不是 `systemctl restart`）；
**但 docker 自己是 systemd 管的**（所以它开机就会自己起来）。
**记住"谁管谁"就不乱：越靠近你的应用的那一层，才是你该动手的那一层。**

### 你只需要会这 5 条命令（任务 8/9/10 会用到）

```bash

docker ps -a                 # 连"已经停了的"一起看
docker logs --tail 50 fangji-api   # 这个容器最近说了什么（排错第一站）
docker port fangji-api       # 实测：8000/tcp -> 0.0.0.0:8009（端口怎么接的）
docker restart fangji-api    # 重启它
```

> ⚠️ **危险命令**（本页最上面那张表里也有）：`docker rm -f $(docker ps -q)` 会**删掉所有容器**。
> 先 `docker ps` 看清楚，再**指定名字**操作。**永远不要用 `-q` 那种"全都来一遍"的写法。**

### 一个容器只有三种状态 —— 对应三组命令

| 状态 | 怎么看出来 | 怎么切过去 |
|------|-----------|-----------|
| **跑着** | `docker ps` 里有它（实测你现在是 `Up 2 months`） | `docker stop fangji-api` |
| **停了** | `docker ps` 里**没有**，但 `docker ps -a` 里有（状态写 `Exited`） | **`docker start fangji-api`** ← 这个才是"启动" |
| **重启**（停一下再起来） | — | `docker restart fangji-api` |

> 📌 **注意 `start` 和 `run` 不是一回事**（初学者最常混的一对）：
> - **`docker start <名字>`** = 把**已经存在的**容器**重新点着**（不改任何东西）
> - **`docker run <镜像>`** = **从镜像造一个全新的容器**（名字、端口都要现给）
>
> **日常 99% 的情况你要的是 `start`。** 用了 `run` 会多出一个**第二个**容器，
> 然后两个抢同一个端口 —— 这是"我就想重启一下，怎么反而崩了"的头号来源。

<details><summary>（了解即可 · <b>先别执行</b>）从零把这个服务跑起来，一共两步</summary>

```bash
docker build -t prescription-api .

# 第 2 步：从镜像造一个容器跑起来
#   -d        后台跑
#   --name    给容器起名
#   -p 8009:8000   宿主 8009 → 容器 8000
docker run -d --name fangji-api -p 8009:8000 prescription-api
```

🔴 **为什么现在别执行**：
① `fangji-api` **已经在跑**，`docker run --name fangji-api` 会报名字冲突；换个名字又会**多占一个端口**
② `docker build` 里那句 `pip install` **要联网重新下载依赖**，慢且可能失败
③ 你现在的服务好好的（`curl` → 200，已跑 65 天）—— **没有问题就不要动它**，
   这正是任务 8/9 想让你学会的判断：**先知道"谁在管它"，再决定要不要动它。**

> 你现在**只需要看懂这两行在干嘛**就够了 —— 它们就是前面那个 Dockerfile 的 ①–⑦ 被真的执行一遍。
</details>

### 任务 6 · 8009 端口被谁占了？

**目标**：查出监听 8009 的进程，拿到它的 **PID**。

**验证**：`sudo ss -tlnp | grep 8009` 的输出里有 `LISTEN`，**并且**有 `pid=数字`

> 🔴 **关键：不加 `sudo` 看不到 PID（2026-10-05 实测）**
> 你会看到两行 `LISTEN`，但 `users:(...)` 那一栏**是空的**。对比 8080 那行就有 `users:(("node",pid=1650,...))`。
> **原因**：占着 8009 的进程是 **root** 的，而 `ss -p` 只显示**你有权限看的**进程。
> **这不是你敲错了，是权限。** 这台机器的 sudo 是免密的，直接加 `sudo`。

**提示**：`ss` 是新一代的 `netstat`。

<details><summary>答案</summary>

```bash
# ① 不加 sudo —— 实测：两行 LISTEN，但【没有 pid】
ss -tlnp | grep 8009

# ② 加 sudo —— 实测：pid 出来了
sudo ss -tlnp | grep 8009
#   LISTEN ... 0.0.0.0:8009  users:(("docker-proxy",pid=1373923,fd=8))     ← IPv4
#   LISTEN ...    [::]:8009  users:(("docker-proxy",pid=1373941,fd=8))     ← IPv6

# 换个工具交叉验证（实测一致）
sudo lsof -i :8009
#   COMMAND     PID USER   FD   TYPE  ...  NAME
#   docker-pr 1373923 root    8u  IPv4  ...  TCP *:8009 (LISTEN)

# 老系统上可能是：
netstat -tlnp | grep 8009
```
**概念**：**PID = 进程编号**，是你在 Linux 里"指认"一个进程的唯一方式。
一个端口同一时刻只能被一个进程监听 —— 所以"端口被占用"的本质是"那个进程还没死"。

🔑 **但这里有个反直觉的结论，任务 7 马上要用到**：
占着 8009 的**不是你的 Python 服务**，而是 **`docker-proxy`** —— Docker 派到宿主上"接客"的传话员。
你的 `uvicorn` 真正跑在**容器里面**（宿主 8009 → 容器 8000）。
⇒ **你会拿到两个不同的 PID，别把它们当成同一个**（任务 7 教你怎么拿另一个）。
</details>

# 微课 3 · 让它自己跑（预计 25 分钟）

**3 个新概念**：① 权限位（rwx / 644 / 755）② shebang 与可执行脚本 ③ cron 定时

### 任务 11 · 读懂 `-rwxr-xr-x` 这串东西

**素材**：用两个**真实存在**的文件对照看。
> ⚠️ 原稿写的是 `ls -l script.sh` —— **那时你还没写脚本呢**，会直接报"没有这个文件"。

**目标**：说出它的权限是什么意思、谁能读谁能写谁能执行。

**验证**：`stat -c "%a %n" 文件名` 输出的数字，和 `ls -l` 的字母能对上

<details><summary>答案</summary>

```bash
ls -l /var/log/syslog /usr/bin/docker
# -rw-r----- 1 syslog adm   2735392  ... /var/log/syslog
# -rwxr-xr-x 1 root   root 45586874  ... /usr/bin/docker
#  ↑↑↑↑↑↑↑↑↑
#  第1位：- 普通文件 / d 目录 / l 链接
#  后 9 位每 3 个一组：所有者(u) / 同组(g) / 其他人(o)
#  r=4  w=2  x=1

stat -c "%a %n" /var/log/syslog /usr/bin/docker
# 640 /var/log/syslog      ← rw- r-- ---
# 755 /usr/bin/docker      ← rwx r-x r-x
```

🔑 **那个 `640` 正好解释了一件你已经遇到过的事**：syslog 的**属组是 `adm`**，
**而你在 `adm` 组里** —— 所以组权限那三位 `r--` 就是**你能读它的原因**。
（对照：`/root` 是 `dr-xr-x--- root root`，你**不在** root 组 → 所以 `cd /root` 会被拒。）

⇒ **读权限的正确顺序：先问"我是谁、我在哪个组"，再去看对应那三位。**
不是"我能不能读这个文件"，而是"**我以什么身份**读这个文件"。

**记忆法**：`755` = `rwxr-xr-x`（4+2+1 / 4+1 / 4+1）；
`644` = `rw-r--r--`（配置文件常见，**谁都不能执行**）。

**⚠️ 不要用 `chmod -R 777`** —— 那是"所有人都能改"，等于把门拆了。
</details>

### 任务 12 · 写第一个脚本

**目标**：写一个脚本：**数出日志里的 ERROR 行数，超过 10 就打印告警**。

> ⚠️ 原稿的 `LOG=/var/log/app.log` **有两处不对**（2026-10-05 实测）：
> ① 那个文件**根本不存在** ② 就算存在，**你也写不了 `/var/log/`**（实测 `touch` → `Permission denied`）
> ⇒ **改用自己的家目录** `$HOME`（登录后就是 `/home/ubuntu`，随便写）。

**先造一份测试日志**（11 行 ERROR，正好超过阈值 10）：

```bash
printf 'ERROR 演示 %s\n' {1..11} > ~/app.log
wc -l ~/app.log        # 实测 11
```

**验证**：跑脚本，应该看到告警

<details><summary>答案</summary>

```bash
#!/bin/bash
# check_errors.sh —— 数 ERROR 行，超过 10 告警
LOG="$HOME/app.log"               # ← 自己的家目录，能读能写
LIMIT=10

COUNT=$(grep -c ERROR "$LOG")     # 实测：对上面那份测试日志 = 11
echo "ERROR 行数：$COUNT"

if [ "$COUNT" -gt "$LIMIT" ]; then
    echo "⚠️ 告警：ERROR 超过 $LIMIT 条！"
fi
```
**概念**：① 第一行 `#!/bin/bash` 叫 **shebang**，告诉系统用哪个解释器跑它
② `$(命令)` 是**命令替换** —— 把命令的输出当成值赋给变量（等价于你 Python 里的函数调用取值）
③ `[ "$COUNT" -gt "$LIMIT" ]` 的数字比较用 `-gt`，**不是 `>`**（`>` 在 shell 里是重定向！这是个经典坑）
④ `$HOME` 是环境变量 —— **cron 里它可能没有值**，所以任务 14 会提醒你脚本里尽量写绝对路径

> 💡 **为什么 `grep -c ERROR` 在这里有值（11），在 `/var/log/syslog` 上却是 0**：
> 因为**这份 ERROR 是你自己造的**。
> 这正是写脚本该有的习惯 —— **先造一份"我知道答案"的输入，再验证输出**
> （跟你写 pytest 是一个思路：**没有可预期的输入，就没法验证**）。
</details>

### 任务 13 · 让它能被执行

**目标**：把任务 12 的脚本变成可以直接 `./check_errors.sh` 跑。

**验证**：`./check_errors.sh` 能跑出结果，而不是报 `Permission denied`

<details><summary>答案</summary>

```bash
chmod +x check_errors.sh     # 只给"执行"权限，别用 777
./check_errors.sh            # ./ 表示"当前目录下的这个文件"

# 如果报 "bad interpreter"，是 shebang 那行写错了或文件有 Windows 换行符
# 修：sed -i 's/\r$//' check_errors.sh
```
**概念**：Linux **不会执行没有 x 权限的文件**，哪怕它是脚本。
**为什么必须写 `./`**：当前目录默认不在 `PATH` 里 —— 这是**安全设计**，
防止你 `cd` 到别人目录里，敲个 `ls` 却跑了他放的恶意脚本。
</details>

### 任务 14 · 让它每 5 分钟自己跑一次

**目标**：用 cron 定时执行任务 12 的脚本，并把结果追加到文件。

> 🔴 **动手前先看这条：你的 crontab 里已经有 3 行别的任务**（2026-10-05 实测）。
> **它们是活的，别删、别改。** 你只在自己那行**下面另起一行**就行。

**验证**：`crontab -l` 能看到你加的那行；等 10 分钟看输出文件有没有变长

<details><summary>答案</summary>

```bash
crontab -l        # 先看现在有什么 —— 实测你已经有这 3 行：
# */2 * * * * /home/ubuntu/gateway-watchdog.sh
# 20 7 * * * /home/ubuntu/.openclaw/workspace/fitness/fitness-remind.sh 0720
# 50 11 * * * /home/ubuntu/.openclaw/workspace/fitness/fitness-remind.sh 1150
#  ↑ 注意它们**全都用 /home/ubuntu/ 这种绝对路径**，没有一行是 /root/
#    —— 这就是"正确写法长什么样"的现成样本，照它的形状写

crontab -e        # 打开编辑器（默认 nano），**在最后另起一行**加：
*/5 * * * * /home/ubuntu/check_errors.sh >> /home/ubuntu/check_errors.out 2>&1
#            ↑ 原稿写的是 /root/check_errors.sh
#              你的账号是 ubuntu，写 /root/ 会因为没权限而**静默失败**（不报错、也不执行）

crontab -l        # 确认加上了（应该从 3 行变成 4 行）
```
> 📝 **nano 怎么用**：方向键移动 → `Ctrl+O` 保存（回车确认）→ `Ctrl+X` 退出。
> 想用 vim 就 `EDITOR=vim crontab -e`。**卡住的话 `Ctrl+X` 能退出，不会弄坏已有任务。**

**概念**：`*/5 * * * *` 五个字段 = **分 时 日 月 周**：
`*/5` 每 5 分钟 ｜ `0 3 * * *` 每天 3 点 ｜ `0 3 * * 1` 每周一 3 点。

**三个必踩的坑**：
- 🔴 **路径要写绝对路径，并且确认自己有权限** —— 原稿的 `/root/check_errors.sh` 在你这台机器上
  就是"**什么都没发生，而且不报错**"，最难查的一类故障
- **`2>&1` 不能省** —— cron 的错误默认发邮件，不写这个你什么都看不到
- **cron 的环境变量和你登录时不一样**（比如 `$HOME` 可能没值）—— 所以脚本里**尽量用绝对路径**
  （这也是为什么任务 12 里 `$HOME` 能用、但更稳的写法是写死 `/home/ubuntu`）

**怎么确认它真的跑了**（等 5 分钟）：
```bash
cat /home/ubuntu/check_errors.out          # 文件变长了 = 真的跑了
grep CRON /var/log/syslog | tail -5        # 或者去看 cron 自己的记录
```
</details>

### 任务 15 · SSH 免密登录

**目标**：配好从本机到服务器的免密登录（不用每次输密码）。

**验证**：`ssh ubuntu@123.58.220.17` 直接进去，不问密码

<details><summary>答案</summary>

```bash
# 1) 本机生成密钥（已有就跳过）
ssh-keygen -t ed25519 -C "我的电脑"

# 2) 把公钥传上去（这一步还会问一次密码）
ssh-copy-id ubuntu@123.58.220.17

# 3) 验证
ssh ubuntu@123.58.220.17 "hostname; uptime"
```
**概念**：`~/.ssh/id_ed25519` 是**私钥，绝不外传**；
`id_ed25519.pub` 是**公钥，就是要给服务器的**。
服务器把它追加到 `~/.ssh/authorized_keys` 里 —— `ssh-copy-id` 就是替你干这件事。

> ⚠️ **用户名是 `ubuntu` 不是 `root`** —— 公钥要传到 `/home/ubuntu/.ssh/authorized_keys`。
> 传到 `/root/.ssh/` 的话，用 `ubuntu` 登录时**照样要密码**（免密是"用户级"的，不是"机器级"的）。
</details>
