## ⚠️ 先看这个：危险命令清单（比学什么更重要）

**在真机上，下面这些一条敲错就可能回不来。练之前先把这张表记住。**

| 命令 | 危险在哪 | 安全替代 |
|------|----------|----------|
| `rm -rf /` 或 `rm -rf *` | **删库跑路**，且 Linux 没有回收站 | 先用 `ls` 看要删什么，再 `rm` 加具体路径 |
| `rm -rf $VAR/`（变量为空） | 变量没值时变成 `rm -rf /` | 用 `rm -rf "${VAR:?}"` —— `:?` 让空值直接报错 |
| `> 文件`（重定向到已存在的文件） | **直接清空原文件**，没有确认 | 先 `cp 文件 文件.bak` |
| `kill -9 <PID>` | 强杀，进程没机会存盘/关连接 | 先 `kill <PID>`（温和），等 5 秒再说 |
| `chmod -R 777 .` | 把整个目录开成谁都能改 | 只用 `chmod +x 某个脚本` |
| `docker rm -f $(docker ps -q)` | 删掉**所有**容器 | 先 `docker ps` 看清楚，再指定名字 |
| `apt install` 输错源 | 可能把依赖搞乱 | 不确定就别装 |

> 🔑 **一条铁律**：**不确定的命令，先在 `--help` 或空跑一遍。**
> 这跟你写代码前的「静态三查」是同一个习惯 —— 只不过这里查的是"这条命令会改什么"。

# 微课 1 · 找到东西（预计 20 分钟）

**这一课只有 3 个新概念**：① 路径（绝对 / 相对 / `~`）② 管道 `|` 与重定向 `>` ③ 看文件的三件工具分工

### 任务 1 · 先搞清楚"我在哪"

**目标**：登进服务器后，回答三个问题 —— 我在哪个目录？这个目录里有什么（**包括隐藏文件**）？我的家目录在哪？

**验证**：把你的答案和下面三条命令的输出对照
```bash
pwd            # 我在哪（print working directory）
ls -la         # 这个目录里有什么，-a 才会显示 . 开头的隐藏文件
echo ~ && cd ~ && pwd   # ~ 是家目录，cd 过去再看一次
```

**提示**：`ls` 不带 `-a` 时**看不到 `.env`、`.git` 这类文件** —— 而你的项目里恰恰有 `.env`。

<details><summary>答案</summary>

```bash
pwd                 # /root  或 /home/xxx
ls -la              # 会看到 . 和 .. 和隐藏文件
cd ~ && pwd         # ~ 展开成 /root（root 用户）或 /home/用户名
```
**概念**：`~` 是 shell 帮你展开的**家目录缩写**；`.` 是当前目录，`..` 是上一级。
</details>

---

### 任务 2 · 找到你的项目在哪

**目标**：不知道项目放哪了 —— 用命令把它找出来。

**验证**：找到后 `cd` 进去，`ls` 能看到 `api.py` 或 `docker-compose.yml`

**提示**：两个方向 —— 按**文件名**找，或按**内容**找。

<details><summary>答案</summary>

```bash
# 按文件名找（从根目录开始，2>/dev/null 是丢掉"没权限"的报错）
find / -name "api.py" 2>/dev/null

# 按文件名找（更快，走数据库，但当天新建的可能没索引）
locate api.py

# 按内容找：哪些 .py 文件里写了 8009
grep -rn "8009" --include="*.py" / 2>/dev/null
```
**概念**：`find` 按名字/时间/大小找，`grep` 按内容找 —— **两个不同的问法，别混**。
</details>

---

### 任务 3 · 看文件，但别用 `cat`

**目标**：有个几百 MB 的日志文件，你要①看它有多少行 ②看最后 20 行 ③**实时**看新写入的行。

**验证**：三条都跑出来；第三条要能看到新内容**自己冒出来**（再开一个终端制造点流量）

**提示**：`cat` 会把整个文件吐到屏幕上 —— 大文件会把终端卡死。

<details><summary>答案</summary>

```bash
wc -l app.log          # ① 行数（word count -l = lines）
tail -20 app.log       # ② 最后 20 行
tail -f app.log        # ③ -f = follow，实时跟踪。Ctrl+C 退出
```
**概念**：看文件的三件工具分工 ——
`cat` 看小文件 ｜ `less` 翻大文件（`q` 退出）｜ `tail` 看末尾、`-f` 追新行。
**排查问题 90% 的时候你要的是 `tail -f`。**
</details>

---

### 任务 4 · 把命令的输出来回倒腾（管道）

**目标**：日志有 5 万行，你要**只看含 ERROR 的行，并且只数有多少条**。

**验证**：屏幕上只出现一个数字

**提示**：两条命令用 `|` 接起来 —— 前一条的输出，变成后一条的输入。

<details><summary>答案</summary>

```bash
grep ERROR app.log | wc -l          # 筛出 ERROR 行 → 数行数

# 变式：先筛再存，然后慢慢看
grep ERROR app.log > errors.txt
wc -l errors.txt
```
**概念**：`|`（管道）= **把左边命令的输出，接到右边命令的输入**。
这是 Linux 最值钱的一个符号 —— 小命令拼起来能干大事。
`>` 是**写入文件**（会覆盖！），`>>` 是**追加**。
</details>

---

### 任务 5 · 磁盘满了？先找出谁占地方

**目标**：服务器提示磁盘满，找出**占空间最大的 3 个目录**。

**验证**：输出 3 行，按大小从大到小排

**提示**：`du`（disk usage）算体积，`sort -rh` 按人类可读的大小**倒序**排。

<details><summary>答案</summary>

```bash
du -sh */ | sort -rh | head -3      # 当前目录下各子目录的体积，取前 3
df -h                                # 顺便看整个磁盘还剩多少
```
**概念**：`-h` = human readable（显示成 1.2G 而不是 1234567）；
`-r` = reverse（倒序），`sort -h` 才能正确比较 `9M` 和 `1.2G`。
**⚠️ `du -sh */` 只扫当前目录一层**，要往下钻就 `cd` 进最大的那个再跑一次。
</details>

# 微课 2 · 看清状况（预计 25 分钟）

**3 个新概念**：① 进程与 PID ② 端口监听 ③ 启动方式（systemd / docker）

### 任务 6 · 8009 端口被谁占了？

**目标**：查出监听 8009 的进程，拿到它的 **PID**。

**验证**：输出里有 `LISTEN` 和 `pid=数字`

**提示**：`ss` 是新一代的 `netstat`。

<details><summary>答案</summary>

```bash
ss -tlnp | grep 8009
# -t TCP  -l 只看监听  -n 显示端口号不解析名字  -p 显示进程

# 老系统上可能是：
netstat -tlnp | grep 8009
lsof -i :8009
```
**概念**：**PID = 进程编号**，是你在 Linux 里"指认"一个进程的唯一方式。
一个端口同一时刻只能被一个进程监听 —— 所以"端口被占用"的本质是"那个进程还没死"。
</details>

---

### 任务 7 · 这个进程是什么时候起的？跑了多久？

**目标**：用任务 6 拿到的 PID，看它的**完整启动命令**和**已运行时长**。

**验证**：能看到 `etime` 形如 `2-03:15:42`（2 天 3 小时…）

<details><summary>答案</summary>

```bash
ps -p <把PID填这里> -o pid,etime,cmd
# 或者直接按名字找
pgrep -af uvicorn        # -a 显示完整命令行，-f 匹配整行
```
**概念**：`ps -o` 是"我要看哪几列" —— 列名可自选，比 `ps aux | grep` 干净得多。
**`etime` 很有用**：如果它显示只跑了几分钟，说明**进程刚重启过**，那问题可能刚发生。
</details>

---

### 任务 8 · 它是怎么被启动的？

**目标**：搞清楚你的服务是用 **systemd** 管的，还是 **docker** 跑的。

**验证**：`systemctl status xxx` 或 `docker ps` 能对上号

<details><summary>答案</summary>

```bash
systemctl list-units --type=service | grep -i -E "api|uvicorn|fastapi"
systemctl status <服务名>          # 看状态、最近日志、启动命令

docker ps                          # 有输出 → 是 docker 跑的
docker logs --tail 50 <容器名>      # 看容器日志
```
**概念**：**知道"谁在管这个进程"才能正确地重启它。**
systemd 管的用 `systemctl restart`；docker 跑的用 `docker restart`。
**用错方式重启 = 起了一个野进程，然后端口冲突。**
</details>

---

### 任务 9 · 正确地重启它

**目标**：把服务重启一次，**且做到"重启前后都没报错、服务真的起来了"**。

**验证**：重启后 `ss -tlnp | grep 8009` 能看到**新的 PID**；`curl -s localhost:8009/docs -o /dev/null -w "%{http_code}"` 返回 200

**提示**：先确认是 systemd 还是 docker（任务 8）。

<details><summary>答案</summary>

```bash
# systemd
systemctl restart <服务名>
systemctl status <服务名> --no-pager | head -20

# docker
docker restart <容器名>
docker logs --tail 30 <容器名>

# 不管哪种，最后都验证一下
ss -tlnp | grep 8009
curl -s -o /dev/null -w "%{http_code}\n" localhost:8009/docs
```
**概念**：**"命令没报错" ≠ "服务起来了"** —— 必须用端口 + HTTP 状态码验证。
这跟你写代码要跑测试是同一个道理。
</details>

### 任务 10 · 一次看清所有 python 进程

**目标**：列出所有 python 相关进程，数一下有几个。

**验证**：先出列表，再出一个数字

<details><summary>答案</summary>

```bash
pgrep -af python          # 列出（含完整命令行）
pgrep -af python | wc -l  # 几个
ps aux | grep python | grep -v grep   # 老写法，grep -v 是为了排掉 grep 自己
```
**概念**：`grep -v` = **反选**（不要含这个词的行）。
`ps aux | grep xxx` 的结果里总有一条是 `grep xxx` 自己 —— 这是新手最常见的困惑。
</details>

# 微课 3 · 让它自己跑（预计 25 分钟）

**3 个新概念**：① 权限位（rwx / 644 / 755）② shebang 与可执行脚本 ③ cron 定时

### 任务 11 · 读懂 `-rwxr-xr-x` 这串东西

**目标**：随便找个文件，说出它的权限是什么意思、谁能读谁能写谁能执行。

**验证**：`stat -c "%a %n" 文件名` 输出的数字，和 `ls -l` 的字母能对上

<details><summary>答案</summary>

```bash
ls -l script.sh
# -rwxr-xr-x  1 root root  123 ... script.sh
#  ↑↑↑↑↑↑↑↑↑
#  第1位：- 普通文件 / d 目录 / l 链接
#  后 9 位每 3 个一组：所有者(u) / 同组(g) / 其他人(o)
#  r=4  w=2  x=1

stat -c "%a %n" script.sh      # 755
```
**记忆法**：`755` = `rwxr-xr-x`（4+2+1 / 4+1 / 4+1）；
`644` = `rw-r--r--`（配置文件常见，**谁都不能执行**）。

**⚠️ 不要用 `chmod -R 777`** —— 那是"所有人都能改"，等于把门拆了。
</details>

---

### 任务 12 · 写第一个脚本

**目标**：写一个脚本：**数出日志里的 ERROR 行数，超过 10 就打印告警**。

**验证**：手工往日志里塞 11 行 ERROR，跑脚本，应该看到告警

<details><summary>答案</summary>

```bash
#!/bin/bash
# check_errors.sh —— 数 ERROR 行，超过 10 告警
LOG=/var/log/app.log
LIMIT=10

COUNT=$(grep -c ERROR "$LOG")
echo "ERROR 行数：$COUNT"

if [ "$COUNT" -gt "$LIMIT" ]; then
    echo "⚠️ 告警：ERROR 超过 $LIMIT 条！"
fi
```
**概念**：① 第一行 `#!/bin/bash` 叫 **shebang**，告诉系统用哪个解释器跑它
② `$(命令)` 是**命令替换** —— 把命令的输出当成值赋给变量（等价于你 Python 里的函数调用取值）
③ `[ "$COUNT" -gt "$LIMIT" ]` 的数字比较用 `-gt`，**不是 `>`**（`>` 在 shell 里是重定向！这是个经典坑）
</details>

---

### 任务 13 · 让它能被执行

**目标**：把任务 12 的脚本变成可以直接 `./check_errors.sh` 跑。

**验证**：`./check_errors.sh` 能跑出结果，而不是报 `Permission denied`

<details><summary>答案</summary>

```bash
chmod +x check_errors.sh     # 只给"执行"权限，别用 777
./check_errors.sh            # ./ 表示"当前目录下的这个文件"

# 如果报 "bad interpreter"，是 shebang 那行写错了或文件有 Windows 换行符
# 修：sed -i 's/\r$//' check_errors.sh
```
**概念**：Linux **不会执行没有 x 权限的文件**，哪怕它是脚本。
**为什么必须写 `./`**：当前目录默认不在 `PATH` 里 —— 这是**安全设计**，
防止你 `cd` 到别人目录里，敲个 `ls` 却跑了他放的恶意脚本。
</details>

---

### 任务 14 · 让它每 5 分钟自己跑一次

**目标**：用 cron 定时执行任务 12 的脚本，并把结果追加到文件。

**验证**：`crontab -l` 能看到你加的那行；等 10 分钟看输出文件有没有变长

<details><summary>答案</summary>

```bash
crontab -e        # 打开编辑器，加一行：
*/5 * * * * /root/check_errors.sh >> /root/check_errors.out 2>&1

crontab -l        # 确认加上了
```
**概念**：`*/5 * * * *` 五个字段 = **分 时 日 月 周**：
`*/5` 每 5 分钟 ｜ `0 3 * * *` 每天 3 点 ｜ `0 3 * * 1` 每周一 3 点。

**两个必踩的坑**：
- **`2>&1` 不能省** —— cron 的错误默认发邮件，不写这个你什么都看不到
- **cron 的环境变量和你登录时不一样**，脚本里**尽量用绝对路径**
</details>

### 任务 15 · SSH 免密登录

**目标**：配好从本机到服务器的免密登录（不用每次输密码）。

**验证**：`ssh root@123.58.220.17` 直接进去，不问密码

<details><summary>答案</summary>

```bash
# 1) 本机生成密钥（已有就跳过）
ssh-keygen -t ed25519 -C "我的电脑"

# 2) 把公钥传上去（这一步还会问一次密码）
ssh-copy-id root@123.58.220.17

# 3) 验证
ssh root@123.58.220.17 "hostname; uptime"
```
**概念**：`~/.ssh/id_ed25519` 是**私钥，绝不外传**；
`id_ed25519.pub` 是**公钥，就是要给服务器的**。
服务器把它追加到 `~/.ssh/authorized_keys` 里 —— `ssh-copy-id` 就是替你干这件事。
</details>

## 一个提醒

`[观点]` **别背命令。** 你自己写代码时也从来不背 `len()` 的用法 —— 你是**知道"有个东西能数字符"**，
用的时候查一下。

Linux 也一样：**要记住的是"有哪类工具"，不是拼写。**
- 找东西 → `find` / `grep` / `locate`
- 看内容 → `cat` / `less` / `tail -f`
- 看状态 → `ps` / `ss` / `df` / `du`
- 改权限 → `chmod` / `chown`

**卡住时的第一反应应该是 `命令 --help` 或 `man 命令`，而不是来问我。**
